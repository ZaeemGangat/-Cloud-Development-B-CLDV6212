You will replace paper menus and filing cabinet documents by creating Azure Storage tables, Azure Blob Storage, and HTTP-triggered Azure Functions running locally in isolated Docker containers via Azurite emulation.Detailed Technical Guidance & Scenario Context1. Scenario Context: Digital Menu & Document ManagementCoffeeNChill staff currently write menu items on chalkboards and print daily paper recipes. To modernize:Menu Items: Must be stored dynamically in Azure Table Storage so prices and availability can be updated instantly across campus.Staff Documents: Operational guidelines (e.g., barista recipe sheets, equipment cleaning manuals, health & safety policies) must be accessible from a centralized Azure Blob Storage.2. Technical Specifications & EndpointsAzurite Storage Setup:Configure local Azure Storage emulation using the official Microsoft Azurite Docker container - https://mcr.microsoft.com/azure-storage/azurite.Ensure connection strings in your local.settings.json file point to AzuriteAzure Table: MenuItemsPartitionKey: Category string (e.g., "Hot Drinks", "Cold Drinks", "Pastries", "Sandwiches").RowKey: Unique Item SKU / ID (e.g., "COF-001", "PAS-104").Name: Item name (e.g., "Espresso", "Ham & Cheese Croissant").Description: Short menu description.Price: Item price (Double/Decimal).IsAvailable: Availability status (Boolean).HTTP Azure Functions Required (Menu):CreateMenuItem (POST /api/menu): Accepts JSON body and inserts a new menu entity into MenuItems.GetAllMenuItems (GET /api/menu): Queries and returns all menu entities.GetMenuItemsByCategory (GET /api/menu/category/{category}): Filters entities by PartitionKey.UpdateMenuItem (PUT /api/menu/{category}/{id}): Updates price or availability status.DeleteMenuItem (DELETE /api/menu/{category}/{id}): Removes an item from the menu.Azure Blob Storage: staff-docsHTTP Azure Functions Required (Documents):UploadStaffDocument (POST /api/documents/upload): Accepts a file upload via multipart/form-data and streams it directly to the staff-docs file share.ListStaffDocuments (GET /api/documents): Lists all stored operational files in staff-docs with file name, size, and last modified date.DownloadStaffDocument (GET /api/documents/download/{fileName}): Streams the requested recipe or manual PDF back to the client.Write Postman tests that test everything to show that everything works.3. Containerization Architecture & Docker Setup (No Docker Compose in Part 1)In Part 1, you must demonstrate how to build and execute individual components as standalone Docker containers without orchestration tools.Azurite Container Execution:Pull and run Azurite in its own isolated container binding default storage ports (10000 for Tables, 10001 for Blobs, 10002 for Queues):docker run -p 10000:10000 -p 10001:10001 -p 10002:10002 https://mcr.microsoft.com/azure-storage/azuriteAzure Functions Containerization:Write a Dockerfile in your Azure Functions project root. Package your compiled C# project using the official Azure Functions base runtime.Build and tag your image, then push it to your public Docker Hub repository:docker build -t <dockerhub_username>/coffeenchill-functions:v1.0 .Running Standalone Function Container:Run your function container independently, passing environment variables so it connects to the Azurite container host:docker run -p 7071:80 -e <dockerhub_username>/coffeenchill-functions:v1.0Part 1 Deliverables Checklist:GitHub Repository link submitted on the learning platform. Minimum 5 meaningful commits per group member verified in Git history. A README.md, formatted neatly using Markdown, containing local setup steps, standalone Docker execution commands, a section containing what each group member worked on, and YouTube video link. Working HTTP Trigger Azure Functions connected to Azurite Table and Azure Blob Storage.Verified Docker Hub link showing a published, tagged container image for your Functions (coffeenchill-functions:v1.0) , as well as the Azurerite image (coffeenchill-Azurite:v1.0)Postman Collection exported (.json) and committed in the /docs folder, verifying all HTTP function endpoints.Your video must demonstrate you running your Docker containers using the ‘docker run’ command, and the successful execution of the items in your Postman collection.Appendix A - PoE Marking Rubrics															Assessment Sheet (Marking Rubric) MODULE NAME:MODULE CODE:CLOUD DEVELOPMENT 2BCLDV6212/wSTUDENT NAME:STUDENT NUMBER:PART 1Marking Criteria Does not meet the required standardMeets the required standard Partially exceeds the required standardGreatly exceeds the required standardFeedbackSubmission, Structure & DocumentationRepository organization & /docsReadme completeness & setup notesGit commit requirements (min 5 per student) Video link & presentation quality [10 Marks]Missing files or broken repository link.
